Watch something and be woken only when something new shows up: "tell me when my boss emails", "watch this price", "let me know about new issues". The server checks on a schedule with one read-only call, without you, and wakes you in this chat only for new matches; what you then say is posted here. Fields: `name` (what is watched, short); `prompt` (what the person wants done or said when it fires, in their words); `tool` (the exact name of a connector read tool, found with tool_search, or "web_fetch") and `args` (its arguments, exactly as you would call it); `everyMinutes` (default 30, at least 15; pick the slowest that still serves the person). A LIST result (mail, issues, events): give `items`, the dot path to the list inside the tool result ("" if the result is the list itself), and `id`, the field that identifies one item (for example "id"). Optional `pattern` keeps only items whose text matches the regular expression. Example: tool "list_issues", args {"repo":"acme/app","state":"open"}, items "issues", id "number". A PAGE (no `items`): the page is woken on when its text changes; `pattern` narrows that to a regular expression the page must match, and `below` to a number the first capture group must be under. Example: tool "web_fetch", args {"url":"https://shop.example/item/9"}, pattern "Price:\\s*\\$([0-9.,]+)", below 50. Without a pattern, any change to a page counts, so avoid pages with a clock or counters. Creating it runs the check once to prove the spec works; what already exists is recorded silently and never wakes you. If that test fails you get the reason and nothing is created: fix the spec. Limits: 10 active monitors; a monitor stops after 30 days and you ask the person whether to renew it. Tell the person plainly what you are watching, how often, and that you will only speak up when something new appears.
