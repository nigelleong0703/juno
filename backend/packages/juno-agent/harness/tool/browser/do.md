Hands one page goal to the browser helper, which chooses the clicks and typing itself. Give it the exact values you know and describe the full end state you want (what the page should show), not which buttons to press. Check the resulting page yourself before you rely on it: a todo is done only when you saw the evidence. If the user asked for the helper and it cannot do a step, say what blocked it. One observable outcome per call. New stage: supply completion, a conjunction of exact observed control predicates, including final panel/control state when relevant; inspect the page first when you do not yet know them. Match uses exact observed label/text/placeholder/name/frame, never transient refs. count means controls in the full collected DOM; value/checked/expanded/disabled require one unique control with that observed property. Prefer browser.act fill for known editable text; use this when page-state/control decisions are needed. If this goal may type, supply exact non-secret strings in values. The helper's own status is only its opinion; only verification.passed establishes the declared end state. A pending stage blocks subsequent do/open. Recover with recover:true, an updated actionable goal and NO completion replacement, or browser.act using ref= hints. read/check cannot clear the factual gate. Unsupported or ambiguous observations stay pending. Sensitive actions use normal approval.
